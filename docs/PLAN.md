# ap-exam-quest 実装指示書

応用情報技術者試験(AP)の科目A(旧・午前)を、通勤中にスマホで楽しく周回するための自分専用アプリ。
この文書は実装担当(Opus)への指示書。迷ったらここに書いてある判断基準に従い、書いていないことは「工期が短くなるほう」を選ぶ。

## 1. 背景と制約

### 利用者
- 1人だけ(リポジトリの持ち主)。非エンジニアのバックオフィス職。ITパスポートと情報セキュリティマネジメントは合格済み。
- 使う場面は通勤中のスマホ。片手操作、1回5分前後、電波が切れても動くこと。
- コードの説明は丁寧に。変更したファイルは全文を見せる。

### 締め切り(動かせない)
応用情報は令和8年度後期が最終回の予定。落ちたら次は別の試験になる。

| 項目 | 日程 |
|---|---|
| 申込 | 2027/1/27〜2/16 |
| 科目A | 2027/2/6〜2/19 |
| 科目B | 2027/3/3〜3/15 |

日程は検索結果ベースで、IPA公式ページでの最終確認はまだ。フェーズ0で確認すること(確認先: https://www.ipa.go.jp/shiken/mousikomi/schedule.html )。

### ここから決まる方針
- **MVPは11月中に使い始められる状態にする。** 作り込みより「毎日使えること」を優先。
- **アプリは科目A専用。** 科目B(長文+記述)はPCで過去問を解く。アプリには入れない。
- **サーバーなし、ログインなし、実行時のAI呼び出しなし。** 解説などAIが書く文章は、問題データを作る時点で生成してJSONに入れておく。
- **2月に入ったら機能追加はしない。**

## 2. コンセプト「ひとり情シス奮闘記」

架空のベンチャー企業で、たった1人の情シス責任者として働く。日々起きる出来事(イベント)に過去問で対処すると会社が育つ。

| 要素 | 中身 | 学習上の役割 |
|---|---|---|
| イベント | 1回5問。冒頭に2〜3行の状況文が出る(例:「営業がカフェにPCを置き忘れた」)。 | 1通勤=1イベントの区切り |
| 未解決インシデント | 間違えた問題が積まれる。 | 誤答の記録 |
| 監査(ボス戦) | 復習期限が来た問題が10問以上たまると発生。復習問題だけ10問。8問以上正解でクリア。 | 間隔反復の本体 |
| 部門マップ | 9つの部門(=シラバスの大分類)のレベルを表示。タップで中分類の内訳。 | 弱点の見える化 |
| 社内Wiki | 正解した問題の用語が解放されて一覧にたまる。検索できる。 | 用語の復習、コレクション欲 |
| 業務たとえ | 解説の中の「あなたの仕事で言うと」欄。 | 理解の定着 |
| 新人に説明する | 解説画面のボタン。Claudeアプリに貼るプロンプトをクリップボードにコピーする。 | 逆授業(アプリ外で実施) |
| 会社の成長 | 正解で評価額が増え、節目で会社のステージが上がる(創業期→…→上場)。 | 継続の動機 |

状況文はあくまで「皮」。問題そのものは過去問を改変せずに出す。

## 3. 問題データの作り方(最重要・最初にやる)

### 確認済みの事実(2026/11/13に実物で確認)
- 過去問は年度別ページからPDFで配布されている。一覧: https://www.ipa.go.jp/shiken/mondai-kaiotu/index.html
- ファイル名の規則は `{年度}{a|h}_ap_am_qs.pdf`(問題)と `..._am_ans.pdf`(解答)。`a` が秋期、`h` が春期。置き場所のフォルダ名は年度ごとに違うので、年度別ページのHTMLからリンクを拾うこと。
- **問題PDFはコピー禁止の設定で暗号化されている。** `pdftotext` では中身が取れない(出力が空になる)。
- **解答PDFはテキストが取れる。** 80問分の正解と分野(T/M/S)が表になっている。
- `pdftoppm` でページを画像にすることはできる(閲覧・印刷は許可されている)。1回分は40ページ。
- 出題の並びは 問1〜50がテクノロジ、51〜60がマネジメント、61〜80がストラテジ。

### 利用条件(IPAのFAQ「その他」より)
- 許諾も使用料も不要。ただし著作権は放棄されていない。
- 出典を明記する。書式例:「出典:令和7年度 秋期 応用情報技術者試験 午前 問3」
- 問題を一部でも改変したら、その旨を明記する。
- PDFのセキュリティ解除方法は提供されない。

### ルール
- **PDFの保護は解除しない。** `qpdf --decrypt` などは使わない。
- 問題文は「ページ画像をClaudeが読んで書き写す」方法でテキスト化する。
- 正解は必ず解答PDFから機械的に取る。書き写しの結果から推測しない。
- 問題文・選択肢は改変しない。書き写しで直してよいのは改行位置だけ。
- 全問題に出典を表示する。

### 手順
1. 年度別ページからAPの問題PDF・解答PDFのURLを集める。
2. PDFを `data-src/` にダウンロードする(このフォルダはgit管理しない)。
3. 解答PDFから「問番号・正解・分野」を取り出す。
4. 問題PDFを `pdftoppm -r 150` でページ画像にする。
5. ページ画像を読み、問題ごとに書き写す。図・表・数式の配置が意味を持つ問題は `hasFigure: true` にする。
6. 書き写しと同時に、解説・誤答の理由・業務たとえ・用語・中分類を生成する。
7. 手順3の正解と結合し、1回分を1ファイルのJSONにする。
8. 検査スクリプトを通す(80問そろっているか、選択肢が4つあるか、正解がア〜エか、必須項目が空でないか)。

### 図表のある問題の扱い
- MVPでは `hasFigure: true` の問題を出題しない。
- フェーズ2で対応する。やり方は「問題部分を画像として切り出して表示し、回答はア〜エのボタンだけ」にする。切り出し位置の特定が難航したら、ページ全体の画像を表示する形に落とす。
- 放置はしない。本番では図表問題も出るので、12月中に必ず入れる。

### 取り込む順番
新しい回から順に。MVPは直近2回(令和7年度の秋・春、160問)で始める。フェーズ2で令和元年度秋期までさかのぼる(令和2年度春期は試験中止で存在しない)。

### 文字起こしの品質対策
- 各問題に「原文を見る」リンクを付ける。リンク先はIPAのPDFのURLに `#page=N` を付けたもの。画像をアプリに抱えない。
- 解説画面に「この問題はおかしい」ボタンを置く。押した問題のIDを記録し、設定画面から一覧をコピーできるようにする。
- 解説・業務たとえには「AI生成」と小さく表示する。

## 4. データ形式

### 問題(1回分を1ファイル、`public/data/2025a.json` のように置く)

```ts
type Question = {
  id: string;            // "2025a-03" (年度+期+問番号)
  source: string;        // "令和7年度 秋期 応用情報技術者試験 午前 問3"
  pdfUrl: string;        // 問題PDFのURL
  pdfPage: number;       // 掲載ページ
  field: "T" | "M" | "S";      // 解答PDFの分野
  major: string;         // 大分類(9種。下の一覧)
  minor: string;         // 中分類(23種。AIが分類)
  hasFigure: boolean;
  stem: string;          // 問題文
  choices: [string, string, string, string];  // ア〜エ
  answer: 0 | 1 | 2 | 3; // 解答PDFから取得
  explanation: string;   // 正解の理由(AI生成)
  whyWrong: [string, string, string, string]; // 各選択肢の正誤理由(AI生成)
  analogy: string;       // 業務たとえ(AI生成)
  terms: { name: string; definition: string }[]; // 1〜3個(AI生成)
};
```

大分類(部門マップの9部門):基礎理論/コンピュータシステム/技術要素/開発技術/プロジェクトマネジメント/サービスマネジメント/システム戦略/経営戦略/企業と法務。
中分類の正式な一覧は、IPAのシラバスで確認してから固定する。

### AI生成文の書き方
- `explanation`:3〜5文。前提知識がITパスポート程度の人が読んで分かる言葉で。
- `whyWrong`:各1〜2文。誤答は「それは何の説明か」まで書く(別の用語の説明になっていることが多い)。
- `analogy`:2〜3文。ベンチャー企業のバックオフィスの場面にたとえる(PCの貸与・回収、SaaSのアカウント管理、契約書のやり取り、入退社手続き、経費精算など)。**実在の社名・個人名・社内事情は書かない。** たとえが苦しい問題(純粋な計算問題など)は、無理にたとえず「解き方のコツ」を書く。
- 計算問題の `explanation` は、式を1行ずつ順に書く。

### 学習記録(端末内に保存)

```ts
type Progress = {
  version: 1;
  questions: Record<string, {
    box: 1 | 2 | 3 | 4 | 5;  // 間隔反復の段階
    due: string;             // 次に出す日 "2026-12-01"
    seen: number;            // 出題回数
    wrong: number;           // 誤答回数
    flagged?: boolean;       // 「おかしい」報告
  }>;
  company: { name: string; valuation: number; eventsCleared: number; auditsCleared: number };
  history: { date: string; answered: number; correct: number }[]; // 日別
};
```

- 保存先は `localStorage` でよい(数千問でも1MB未満に収まる)。
- 設定画面に「書き出し(JSONをコピー)」と「読み込み(貼り付け)」を付ける。機種変更やデータ消失への保険。

## 5. 出題ロジック

### 間隔反復
- 5段階。正解で1段上がり、誤答で段階1に戻る。
- 次に出すまでの日数は、段階1から順に 1日、3日、7日、14日、30日。
- 初めて解いて正解した問題は段階2から始める。

### イベント1回(5問)の選び方
1. 復習期限が来ている問題から最大3問。
2. 残りは未出題の問題。そのイベントの部門から選ぶ。
3. 未出題がなくなった部門は、段階の低い問題で埋める。

イベントの部門は、レベルの低い部門が出やすいように重みを付けて決める。利用者が部門マップから部門を指名して始めることもできる。

### 監査
- 復習期限が来ている問題が10問以上あると、ホームに「監査が来た」と出る。
- 無視して通常イベントもできるが、20問を超えたら監査を先にやらないと通常イベントを始められない。

### 部門レベル
その部門の出題対象問題のうち、段階3以上の問題の割合。0〜100%をそのままレベル表示にする。

### 会社の成長
- 正解1問ごとに評価額が増える。復習問題の正解は多め、監査クリアはボーナス。
- ステージの節目は、全問題の何割が段階3以上になったかで決める(評価額はただの演出)。
- 数字の細かい調整はフェーズ2で。MVPは仮の値でよい。

## 6. 画面

| 画面 | 内容 |
|---|---|
| ホーム | 会社名とステージ、今日解いた数、「次のイベントへ」ボタン、監査の通知、試験日までの残り日数 |
| イベント開始 | 状況文と部門名 |
| 出題 | 問題文、ア〜エの大きなボタン(画面下寄せ)、進み具合(3/5) |
| 解説 | 正誤、正解、解説、各選択肢の理由(折りたたみ)、業務たとえ、解放された用語、出典、「原文を見る」「新人に説明する」「おかしい」 |
| イベント結果 | 正解数、評価額の増加、新しく解放された用語 |
| 部門マップ | 9部門のレベル。タップで中分類の内訳と「この部門で始める」 |
| 社内Wiki | 解放済み用語の一覧と検索。未解放は「???」で数だけ見せる |
| 設定 | 会社名、記録の書き出し・読み込み、報告した問題の一覧、出典とライセンスの表記 |

### 操作の決まり
- 片手の親指で全部押せること。押す場所は画面の下半分に集める。
- 回答したらすぐ解説を出す。確認ダイアログは挟まない。
- 途中でアプリを閉じても、同じイベントの続きから再開できる。
- 文字は大きめ(本文16px以上)。ダークモード対応。
- 演出は軽く。待たせるアニメーションは入れない。

### 「新人に説明する」でコピーする文面(たたき台)

```
あなたは入社1年目の新人です。私が今から「{用語}」を説明するので、
分からない点を1つずつ質問してください。3往復したら、私の説明の
正確さを100点満点で採点し、抜けていた点を教えてください。
参考(私には見せないこと):{definition}
```

## 7. 技術構成

- Vite + React + TypeScript。見た目はTailwind CSS。
- PWA化(`vite-plugin-pwa`)。問題データも含めてオフラインで動かす。
- 公開先はGitHub Pages。mainへのマージで自動デプロイ(GitHub Actions)。
- テストはVitest。出題ロジックと間隔反復の計算には必ず付ける。画面のテストは不要。
- データ作成用のスクリプトは `scripts/` に置く。アプリ本体とは混ぜない。

### 最初に確認すること
- リポジトリが非公開の場合、GitHub Pagesは有料プランでないと使えない。使えなければ持ち主に「公開リポジトリにする」か「Cloudflare Pagesにする」かを聞く。公開にしても、載るのは出典付きの過去問と一般的な解説だけなので支障はない想定。

### フォルダ構成(目安)

```
docs/PLAN.md          この文書
scripts/              PDF取得、解答抽出、検査
data-src/             ダウンロードしたPDFとページ画像(git管理しない)
public/data/          問題JSON、イベント状況文JSON
src/logic/            間隔反復、出題選択、成長計算(テスト付き)
src/screens/          各画面
src/storage/          学習記録の読み書き
```

## 8. 工程

| フェーズ | 期限 | 内容 | 完了の条件 |
|---|---|---|---|
| 0 | 着手日 | 日程のIPA公式確認、Pagesの可否確認、中分類一覧の確定 | 3点の結果を持ち主に報告 |
| 1 (MVP) | 11/30 | データ作成の仕組み、直近2回分160問、出題、解説、間隔反復、イベントと監査、ホーム、記録の保存、デプロイ | 下の受け入れ条件 |
| 2 | 12/31 | 部門マップ、社内Wiki、「新人に説明する」、図表問題、令和元年度秋期までの問題追加、成長バランス調整 | 図表問題が出題される。問題数900以上 |
| 3 | 1/24 | 合格ライン予測、年度別の通し演習、再出題問題の印付け | 予測得点がホームに出る |
| 凍結 | 2/1〜 | 不具合修正のみ | — |

### MVPの受け入れ条件
- スマホのホーム画面に追加でき、機内モードでも1イベント完走できる。
- 5問解いて結果画面まで行ける。途中で閉じても再開できる。
- 間違えた問題が翌日以降に再出題される(テストで確認)。
- 全問題に出典が表示され、「原文を見る」でIPAのPDFが開く。
- 正解データが解答PDFと全問一致している(検査スクリプトで確認)。
- 学習記録を書き出して、消して、読み込んで元に戻せる。

### フェーズ3の補足
- 合格ライン予測:分野別の直近正答率に、本番の出題数(T50・M10・S20)を掛けて予測得点を出す。合格は60点(48問正解)。
- 再出題の印付け:複数の回に同じ問題が出ていたら「頻出」とし、Wikiのレア度に使う。同一判定はAIに任せ、迷うものは別問題として扱う。

## 9. やらないこと

- 科目B対策、記述の採点
- ログイン、複数人対応、端末間の自動同期
- 実行時のAI呼び出し、APIキーの保持
- 通知、ランキング、課金
- 問題文の改変や創作問題

## 10. 進め方

- mainには直接入れず、作業ブランチからプルリクエストで入れる。
- 1つのプルリクエストは1つの目的に絞る。目安は「データ作成」「出題と間隔反復」「ゲームの皮」「デプロイ」の4本。
- データ作成は1回分(80問)を先に最後まで通し、持ち主に10問ほど見てもらってから量産する。解説と業務たとえの書きぶりはここで決める。
- 問題の書き写しは量が多いので、ページ範囲ごとに分担させてよい。分担させた結果は必ず検査スクリプトに通す。
